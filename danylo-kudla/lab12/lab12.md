## Хід роботи

1. Опрацьовано твірні шаблони, які відокремлюють процес використання об'єктів від процесу їх створення. Їхня головна мета полягає зробити так, щоб система знала лише про інтерфейси об'єктів з якими працює і нічого не знала про їхні конкретні класи та способи інстанціювання.
2. Фабричний метод являє собою твірний патерн проєктування, який надає загальний інтерфейс для створення об'єктів у базовому класі та дозволяє підкласам визначати їхній конкретний тип. 
<br>У моїй роботі цей патерн розв'язує проблему створення різних типів об'єктів без жорсткої прив'язки клієнтського коду до їхніх конкретних класів. 
<br>Якщо не використовувати фабричний метод дану проблему можна було б вирішити шляхом створення екземплярів через умовні оператори та прямий виклик конструкторів у місцях їх використання. Використання фабричного методу обумовлене, щоб інкапсулювати логіку створення об'єктів в одному місці і забезпечити можливість розширення програми без зміни існуючого коду.
<br>Приклад реалізованого фабричного шаблону на основі сповіщень [lab12](lab12.py). На Рис. 1 зображено абстрактний клас NotificationSend, який використовує інтерфейс Notification для відправки повідомлень, залишаючи створення конкретних об'єктів SMS, Telegram своїм класам-нащадкам SMSSender, TelegramSender.

```mermaid
classDiagram
    direction TB

    class Notification {
        <<abstract>>
        +send(message)
    }
    class SMS {
        +send(message)
    }
    class Telegram {
        +send(message)
    }
    
    class NotificationSend {
        <<abstract>>
        +create_notification() Notification
        +notify_user(message)
    }
    class SMSSender {
        +create_notification() Notification
    }
    class TelegramSender {
        +create_notification() Notification
    }
    
    Notification <|-- SMS
    Notification <|-- Telegram
    
    Notification <.. NotificationSend : Працює через абстракцію
    
    NotificationSend <|-- SMSSender
    NotificationSend <|-- TelegramSender
    

    SMS <.. SMSSender : Створює
    Telegram <.. TelegramSender : Створює
```
Рис. 1 - UML-діаграма класів з реалізацією патерну "Фабричний метод" для створення сповіщень
## Висновок
У підсумку виконання лабораторної роботи ознайомився з п'ятьма твірними шаблонами, а саме: фабричний метод, абстрактна фабрика, прототип, будівельник, одинак. На практиці навчився працювати з фабричним методом, що дало змогу опанувати механізм створення об'єктів підкласам.
