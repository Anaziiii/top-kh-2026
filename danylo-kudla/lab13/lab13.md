## Хід роботи

1. Структурні шаблони відповідають за те, як збирати класи та об'єкти у більші, складніші структури, зберігаючи структури гнучкими та ефективними.
2. Структурний шаблон **міст** розділяє абстракцію та реалізацію на дві незалежні частини, надаючи можливість обом компонентам масштабуватися незалежно одне від одного. 
<br>У коді цей патерн вирішує проблему кількості класів, який неминуче виник би при спробі поєднати всі можливі типи пультів із різними керованими пристроями.
<br>Без використання цього підходу кожен раз довелося б створювати окремий монолітний клас для кожної можливої комбінації через багаторівневе наслідування, такі класи, як _BasicTVRemote_, _AdvancedTVRemote_ чи _AdvancedRadioRemote_.
<br>Застосування шаблону Міст є необхідним, оскільки об'єднання ієрархії абстракції (пультів) та ієрархії реалізації (пристроїв) через механізм композиції дозволяє вільно додавати нову техніку або розширені інтерфейси управління без модифікації вже існуючого коду.
<br>Приклад реалізованого моста на основі пульта та пристрою [lab13](lab13.py).

```mermaid
---
title: UML-діяграма класів з реалізацією патерну "міст" для пульта та присторою

classDiagram
    class Device {
        <<interface>>
        +turn_on()
        +turn_off()
        +set_channel(channel)
    }
    
    class TV {
        +turn_on()
        +turn_off()
        +set_channel(channel)
    }
    
    class Radio {
        +turn_on()
        +turn_off()
        +set_channel(channel)
    }
    
    class RemoteControl {
        #device: Device
        +power_on()
        +power_off()
        +channel(number)
    }
    
    class AddRemoteControl {
        +mute()
    }
    
    %% Зв'язки
    RemoteControl o--> Device : 
    RemoteControl <|-- AddRemoteControl : 
    Device <|.. TV : 
    Device <|.. Radio : 
```
## Висновок
У підсумку виконання лабораторної роботи ознайомився з сімома патернами, а саме: адаптер, міст, компонувальник, декоратор, фасад, легковаговик, замісник. На практиці навчився використовувати патерн "міст" з реалізацією роботи пульта та пристрою, що дало змогу розділити клієнтський інтерфейс та внутрішню реалізацію з можливістю гнучкої підтримки.
