## Короткі теоретичні відомості

Рефакторинг являє собою процес поліпшення внутрішньої структури та читабельності коду без зміни його поведінки та існуючої функціональності. Його базові принципи полягають у внесенні дрібних, змін для усунення "запахів коду", що підкріплюється регулярним тестуванням для збереження стабільності системи.

## Хід роботи

1. Завдання взято з курсової роботи, під час виконання якої стикнувся з проблемою складності потоку виконання та низької читабельності коду. Для вирішення цієї проблеми було проведено рефакторинг: усунуто вкладеність умов, приховані точки виходу з циклу замінено на явне керування станом, а негативні умови перетворено на позитивні для легшого сприйняття.
<br> У першому варіанті наведено код до рефакторингу.
```python
    def run(self):
        while True:
            if not self.session_manager.is_authenticated():
                if not self._show_quest_menu():
                    break
            else:
                if not self._show_user_menu():
                    break
```
<br> Другий варіант після проведеного рефакторингу.

```python
    def run(self):
        is_running = True
        while is_running:
            if self.session_manager.is_authenticated():
                is_running = self._show_user_menu()
            else:
                is_running = self._show_quest_menu()
```
3. "Запах коду" як певна ознака, яка вказує на потенційні проблеми вихідного коду програми на його архітектуру або дизайн, хоча програма може працювати коректно. Наприклад взяти "запах" **дублювання коду** який є найпоширенішим та найнебезпечнішим. Його суть полягає в тому, що однаковий або структурно дуже схожий фрагмент коду зустрічається у двох або більше місцях програми, що може бути пряме копіювання або написання тієї ж самої логіки іншими словами. Небезпека полягає у порушенні принципу програмування DRY, якщо в здубльованій логіці знайдено помилку, або вимоги змінилися, потрібно буде шукати і виправляти всі місця, де цей код скопійовано.

## Висновок
У підсумку виконання лабораторної роботи ознайомися з принципами рефакторингу. Під час лабораторної роботи навчився виявляти проблемні ділянки коду, які потребують покращення зокрема надмірну вкладеність, заплутаний потік управління та неявні умови виходу з циклів.
