ТЕМА 11. Принципи проєктування програмного забезпечення

Мета роботи: познайомитися з найбільш поширеними сучасними принципами проєктування програмного забезпечення.

Виконання завдання

1. Загальний опис принципів проєктування

Принципи проєктування — це набір правил і рекомендацій, які допомагають програмістам писати чистий, зрозумілий і легкий у підтримці код.
Основні базові принципи:

KISS (Keep It Simple, Stupid) — роби код максимально простим, не ускладнюй без потреби.
DRY (Don't Repeat Yourself) — не повторюй себе. Якщо один і той самий код використовується двічі, винеси його у функцію або клас.
YAGNI (You Aren't Gonna Need It) — не пиши функціонал «на майбутнє», якщо він не потрібен просто зараз.
SOLID — це 5 основних принципів ООП:

S (Single Responsibility) — один клас = одна задача.
O (Open-Closed) — класи відкриті для розширення (наслідування), але закриті для зміни їхнього початкового коду.
L (Liskov Substitution) — об'єкти дочірніх класів повинні без проблем замінювати об'єкти батьківських класів.
I (Interface Segregation) — краще багато маленьких спеціалізованих інтерфейсів, ніж один величезний.
D (Dependency Inversion) — класи повинні залежати від абстракцій, а не від конкретних деталей реалізації.

2. Детальний опис принципу SOLID з прикладом коду

Проаналізовано суть принципу єдиної відповідальності (Single Responsibility Principle) із набору SOLID.   
Створено початковий клас BadReport, який порушує цей принцип, поєднуючи в собі логіку зберігання тексту звіту та роботу з файловою системою.
Проведено розділення відповідальності: створено клас Report (відповідає виключно за зберігання даних звіту) та клас ReportSaver зі статичним методом save_to_file() (відповідає лише за запис даних у файл).

Суть: Кожен клас повинен відповідати лише за одну задачу.
