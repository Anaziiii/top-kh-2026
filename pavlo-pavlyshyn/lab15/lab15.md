## Хід роботи 

1. Опрацьовано поняття рефакторингу. **Рефакторинг** - це зміна внутрішньої будови коду, після якої програма працює так само, як і раніше, але сам код стає чистішим і простішим для підтримки. Основні правила:
    - результат роботи програми до і після має бути однаковим;
    - зміни вносяться маленькими кроками, після кожного кроку код перевіряється;
    - рефакторинг не поєднують з додаванням нового функціоналу;
    - бажано мати тести, які підтвердять, що нічого не зламалось.
2. Розглянуто "запахи коду" - ознаки того, що код варто переписати:

    | Запах | Опис |
    |-------|------|
    | **Magic Numbers** | у коді стоять числа, значення яких незрозуміле |
    | **Long Method** | функція занадто довга і робить кілька справ одразу |
    | **Duplicate Code** | один і той самий фрагмент повторюється |
    | **Poor Naming** | назви змінних і функцій нічого не пояснюють |
    | **Large Class** | клас відповідає за все підряд |
    | **Long Parameter List** | у функції забагато параметрів |

3. Розглянуто поширені техніки рефакторингу: **Extract Method**, **Rename Variable/Method**, **Replace Magic Number with Symbolic Constant**, **Decompose Conditional**, **Extract Class**, **Move Method**, **Replace Conditional with Polymorphism**.
4. Для практичної частини взято функцію, яка рахує вартість перебування собаки в готелі для тварин. Початковий варіант:

    ```python
    def calc(w, d, v):
        if w < 10:
            p = 250 * d
        elif w < 25:
            p = 350 * d
        else:
            p = 450 * d
        if d >= 7:
            p = p - p * 0.1
        if not v:
            p = p + 200
        return p
    ```

5. У цьому коді знайдено такі запахи:
    - назви **calc**, **w**, **d**, **v**, **p** не пояснюють, що саме рахується;
    - числа **10**, **25**, **250**, **0.1**, **200** та інші записані прямо в коді, і без автора не зрозуміло, що вони означають;
    - одна функція одразу визначає тариф, рахує знижку і додає доплату.
6. Застосовано три техніки, результат збережено у файлі [lab15](lab15.py):
    - **Rename** - функцію названо **stay_price**, параметри - **weight**, **days**, **vaccinated**;
    - **Replace Magic Number with Symbolic Constant** - усі числа винесено в константи з назвами (**SMALL_DOG_RATE**, **LONG_STAY_DISCOUNT**, **NO_VACCINE_FEE** тощо);
    - **Decompose Conditional** та **Extract Method** - кожну умову винесено в окрему функцію: **day_rate**, **long_stay_discount**, **vaccine_fee**.
7. Після рефакторингу основна функція складається з трьох рядків і читається як опис розрахунку:

    ```python
    def stay_price(weight, days, vaccinated):
        price = day_rate(weight) * days
        price -= long_stay_discount(price, days)
        price += vaccine_fee(vaccinated)
        return price
    ```

8. Для однакових вхідних даних старий і новий варіант повертають однаковий результат, тобто поведінка програми не змінилась.

## Висновок
У підсумку виконання лабораторної роботи ознайомився з принципами рефакторингу, "запахами коду" та основними техніками їх усунення.

На практиці переписано функцію розрахунку вартості готелю для собак: змінено назви, магічні числа замінено константами, а умови винесено в окремі функції. Тепер, щоб змінити тариф чи розмір знижки, достатньо виправити одну константу, а не шукати потрібне число по всьому коду.
