**Мета роботи** - ознайомитися із техніками тестування програмного коду.

## Хід роботи 

1. Опрацьовано поняття тестування - перевірки того, що програма поводиться так, як від неї очікують, і пошуку помилок до того, як їх знайде користувач.
2. Розглянуто рівні тестування та піраміду тестування:

    | Рівень | Що перевіряє | Кількість тестів |
    |--------|--------------|------------------|
    | **Unit-тести** | окрему функцію, метод чи клас | найбільше, вони найшвидші |
    | **Інтеграційні тести** | спільну роботу кількох модулів | менше |
    | **Системні (E2E) тести** | програму цілком, як її бачить користувач | найменше, вони найповільніші |

    Піраміда означає, що основу мають складати швидкі та дешеві unit-тести, а повільних тестів усієї системи має бути небагато.
3. Для практичної частини використано модуль **unittest**, який входить до стандартної бібліотеки Python.
4. У файлі [lab16](lab16.py) створено клас **Shelter** (притулок) на основі класу **Dog** з попередніх лабораторних. Притулок має обмежену кількість місць і методи:
    - **take_in** - прийняти собаку (помилка, якщо місць немає або кличка вже зайнята);
    - **find** - знайти собаку за кличкою;
    - **give_away** - віддати собаку новим господарям;
    - **free_places** - кількість вільних місць;
    - **by_breed** - список собак заданої породи;
    - **average_age** - середній вік собак.
5. У файлі [testlab16](testlab16.py) створено клас **TestShelter**, успадкований від **unittest.TestCase**. У методі **setUp** перед кожним тестом створюється новий притулок на 3 місця з двома собаками, тому тести не впливають один на одного.
6. Написано 10 тестів. Перевіряються як звичайні ситуації, так і помилкові:
    - **assertEqual** - кількість вільних місць, пошук за породою, середній вік;
    - **assertIsNone** - пошук собаки, якої немає;
    - **assertRaises** - прийом собаки в заповнений притулок, повтор клички, видача неіснуючої собаки.
7. Тести запускаються з папки **lab16** командою:

    ```bash
    python -m unittest testlab16 -v
    ```

8. Результат запуску:

    ```
    test_average_age ... ok
    test_average_age_empty_shelter ... ok
    test_by_breed ... ok
    test_find_existing_dog ... ok
    test_find_missing_dog ... ok
    test_free_places ... ok
    test_give_away ... ok
    test_give_away_missing_dog ... ok
    test_take_in_duplicate_name ... ok
    test_take_in_when_full ... ok

    ----------------------------------------------------------------------
    Ran 10 tests in 0.000s

    OK
    ```

## Висновок
У підсумку виконання лабораторної роботи ознайомився з видами тестування та пірамідою тестування, навчився писати unit-тести за допомогою модуля **unittest**.

Для класу **Shelter** написано 10 тестів, усі вони пройшли успішно. Переконався, що важливо перевіряти не тільки правильні сценарії, а й граничні випадки: порожній притулок, заповнений притулок, неіснуюча собака. Наявність тестів дає змогу надалі змінювати код і одразу бачити, чи нічого не зламалось.
