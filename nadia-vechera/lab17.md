1. Ознайомлення з видами тестів та пірамідою тестування

Модульні (Unit) тести: тестують найменші ізольовані фрагменти коду (окремі функції, методи або класи) окремо від решти системи. Вони виконуються дуже швидко та допомагають локалізувати помилки ще на етапі написання коду.

Інтеграційні тести: перевіряють правильність взаємодії між кількома різними модулями чи компонентами програми (наприклад, роботу функції разом із базою даних чи зовнішнім API).

Системні (End-to-End / E2E) тести: оцінюють роботу всієї системи в цілому в умовах, максимально наближених до реального використання кінцевим користувачем.

Піраміда тестування: це концепція, яка визначає ідеальну пропорцію різних видів тестів у проєкті. Вона складається з широкої основи (велика кількість швидких і дешевих у підтримці unit-тестів), середньої частини (помірна кількість інтеграційних тестів) та вузької верхівки (невелика кількість повільних і дорогих системних чи UI-тестів).

2. Написання та виконання unit-тестів на Python 3 за допомогою вбудованого модуля unittest.

Модуль unittest — це вбудована бібліотека Python для написання та автоматичного запуску модульних тестів (створена за аналогією з JUnit).

Для створення наборів тестів створюється клас, який успадковується від unittest.TestCase.

Методи тестування обов'язково мають починатися з префікса test_.

Для перевірки результатів використовуються спеціальні методи перевірки (assertions), такі як assertEqual(a, b), assertTrue(x), assertIn(item, list) тощо.

Запуск тестів виконується за допомогою виклику unittest.main() у блоці if name == '__main__': або через термінал командою python -m unittest.

Модульний unit тест що відповідає за автоматичну перевірку, чи правильно працюють окремі функції програми (add та is_even), щоб не перевіряти їх вручну після кожного змінення коду.

1. Функції, які підлягають тестуванню

У цій секції визначено дві прості функції, які ми будемо перевіряти:

add(a, b) — приймає два числа і повертає їхню суму (return a + b).

is_even(number) — перевіряє, чи ділиться число на 2 без залишку (number % 2 == 0). Якщо так, повертає True (парне), якщо ні — False (непарне).

2. Клас для написання unit-тестів (TestMathAndLogicFunctions)

Цей клас успадковується від unittest.TestCase, що перетворює його на контейнер для тестів. Усередині нього створюються методи, назви яких обов'язково повинні починатися з префікса test_ (інакше фреймворк їх не помітить).

Метод test_add(self) перевіряє роботу функції додавання:

self.assertEqual(add(3, 5), 8) — тут у коді пропущено очікуваний результат 8, але перевірка має порівнювати результат add(3, 5) із числом 8. Якщо вони рівні — тест пройдено.

self.assertEqual(add(-1, 1), 0) — перевіряє додавання від'ємного й додатного чисел.

self.assertEqual(add(-5, -5), -10) — перевіряє додавання двох від'ємних чисел.

Метод test_is_even(self) - перевіряє функцію визначення парності:

self.assertTrue(is_even(4)) — перевіряє, чи результат є об'єктом True (оскільки 4 — парне).

self.assertTrue(is_even(0) — нуль вважається парним числом.

self.assertFalse(is_even(3)) — перевіряє, чи результат є False (оскільки 3 — непарне).

self.assertFalse(is_even(-5)) — перевіряє від'ємне непарне число.

3. Точка входу для запуску тестів
Python

if __name__ == "__main__":
    unittest.main()

Ця стандартна конструкція говорить Python: «Якщо цей файл запускається напряму (а не імпортується як модуль в інший файл), запустить усі знайдені тести через unittest.main()».

Чому саме так?

Ізольованість: Функції тестуються окремо від решти програми. Якщо щось зламається, ви одразу побачите, яка саме функція (і який саме тест) дала збій.

Автоматизація: Вам не потрібно щоразу вручну викликати print(add(3, 5)) у консолі — Python сам виконає всі перевірки за секунду.

Стандартизація (unittest): Використання спеціальних методів на кшталт assertEqual, assertTrue чи assertFalse робить код читабельним і виводить чіткі звіти про помилки, якщо очікуваний результат не збігається з реальним.
